# 黄金矿工辅助线

为 Gold Miner 提供扇形参考线和实时方向线的桌面小工具。实时方向线识别张开的灰色夹子，沿夹口中垂线指向矿区；透明窗口校准后锁定，鼠标可以直接操作下方游戏。

## 使用

1. 以窗口化或无边框窗口化方式打开游戏。
2. 启动 Goldline，拖动绿色覆盖框顶部的拖动条，使边框对齐游戏画面，**不包含系统标题栏**。拖动四边或四角调整大小。
3. 把圆心拖到钩爪的悬挂轴心。此版本默认轴心在画面宽度的 50%、高度的 14%，适用于参考图所示布局，实际位置请微调。
4. 调整数量、展开角度、整体偏转、线长和样式，点击「锁定 · 开始游戏」。校准边框消失，鼠标穿透覆盖窗口。
5. 需要移动窗口或轴心时，点击「重新校准」。窗口找不到时点击「找回覆盖窗口」。控制面板同样置顶，可移到游戏旁边。

校准时空白处和辅助线也能穿透鼠标，直接点击下方游戏。只有顶部拖动条、外框缩放边缘、圆心和黄色识别框接收鼠标；黄色框内可拖动整个识别框。拖动控件时移出其范围不会中断，松开后恢复按区域穿透。锁定后整个覆盖层穿透。

| 快捷键 | 功能 |
| --- | --- |
| Ctrl + Shift + G | 显示 / 隐藏辅助线 |
| Ctrl + Shift + L | 校准 / 锁定，并显示辅助线 |

Mac 上同样使用 Control，不是 Command。快捷键冲突时面板会提示，仍可使用按钮。关闭控制面板即退出应用。

角度以竖直向下为 0°，正值向右。线长 100% 等于覆盖框的对角线长度，超出框的部分自动裁切。展开角度是可调参考范围，不代表已经测量游戏实际摆幅。偶数条射线没有正中央的射线；奇数条时中央射线略粗、略亮。

参数和覆盖窗口位置自动保存于本机；每次启动进入校准模式。更换显示器后窗口恢复到可见区域。恢复默认参数不会改变窗口位置。

本工具不识别金块、不选择目标、不自动按键，不承诺覆盖独占全屏游戏。游戏自身移动或缩放后，请重新对齐覆盖框。

## 实时方向线

1. 勾选「开启识别」。Mac 首次使用时会请求屏幕录制权限；在系统设置中允许 Goldline 后，可能需要退出并重新打开应用。Windows 无需 Python 或额外识别运行时。
2. 在校准模式下，拖动**黄色夹子识别框**，覆盖整个夹子的摆动范围，包含两侧夹爪及尖端。无需对准小绳段或轴心。拖动四边或四角调整宽高，尽量避开轮子和其他灰色物体。
3. 主界面的「识别预览」在校准时也会更新：原图叠加绿色匹配区域轮廓、橙色灰色候选、粉色夹口连线和黄色中垂线。可点击「查看原图」对照；同时显示角度、匹配分数、灰色区域数量和采集/识别耗时。分数不是正确率。
4. 也可输入「左侧位置」「顶部位置」「识别框宽度」「识别框高度」，四项均为游戏画面宽高的百分比。默认位置为 (41%, 12%)，宽高各 18%，随覆盖窗口同比缩放并限制在画面内。首次读取旧版短线配置时会扩大过小的识别框，保留扇形参数及窗口位置。
5. 点击「锁定 · 开始游戏」。识别成功后，黄色线从夹口两端的中点出发，垂直于两端连线并向矿区延长；面板显示当前角度。向左为负，向右为正。

默认在识别时隐藏扇形参考线，可在「识别调整」中重新打开。整个识别框及其边缘保留透明空白，避免辅助线被截入识别画面；黄色线从框外继续显示。不要用其他窗口挡住夹子，控制面板遮挡时会提示。

算法用灰色分割、连通轮廓和双爪形状匹配寻找夹口两端，再计算两端连线的中垂线。既不依赖短绳，也不依赖手动扇形轴心。只看到一侧、夹子被截断、多个候选无法区分、画面过期或截图过慢时，方向线会隐藏；隐藏窗口或关闭识别时暂停截图。校准期间只更新面板预览，不在游戏上绘制识别方向线。画面只在本机内存中处理，不保存或上传。

预览会区分未找到灰色区域、轮廓未匹配、多个候选、采集失败与处理过慢。即使没匹配夹子，只要截图成功也显示原图和候选轮廓；超过 1.5 秒没有新画面会标记「已过期」并隐藏旧标注。灰色分割可能把相连的支架算进同一轮廓，预览可帮助发现这类干扰。

当前针对参考游戏中**张开的灰色双爪夹子**。闭合、夹住物体、被遮挡或更换夹子外观时可能无法识别，不会沿用旧方向。识别不稳定时，先完整框住两侧夹爪并排除其他灰色物体，再尝试「灰色容差」（默认 24）：漏识别时略调高、把背景混入时调低。识别参数会保存，开关每次启动默认关闭。真实摆动及 Windows 画面仍需实机校准。

## 本地开发（Mac / Windows）

需要 Node.js 22、pnpm 11.9.0 和 Rust stable。Mac 需要 Xcode Command Line Tools；Windows 需要 Visual Studio Build Tools 的「使用 C++ 的桌面开发」、Windows SDK 和 WebView2 Runtime。

```sh
pnpm install
pnpm tauri dev
```

Mac 也可以使用 `make dev`。仅运行 `pnpm dev` 是前端开发服务器，不具备原生窗口功能。

```sh
pnpm build
pnpm test
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
```

## 打包

Mac：

```sh
pnpm tauri build --bundles app
```

在原生 Windows x64 环境构建 Windows 10 安装包：

```powershell
pnpm install --frozen-lockfile
pnpm tauri build --bundles nsis
```

安装包位于 `src-tauri/target/release/bundle/nsis/`。安装器在缺少 WebView2 时下载并安装运行时，需要网络连接。安装包未配置代码签名。

仓库提供 Windows GitHub Actions 工作流，可手动运行，或推送 `v*` 标签触发；生成安装包作为工作流附件，不自动发布 Release。Mac 本地构建不能证明 Windows 10 实机兼容性。

## 配置与实现

- React + TypeScript + SVG 绘制；Tauri 2 / Rust 管理透明覆盖窗口、全局快捷键与配置。
- 控制面板与覆盖层通过 Tauri 命令和带版本的状态事件同步。
- 实时识别使用 Rust + XCap：Windows 采用 GDI 区域截图，Mac 采用 CoreGraphics 并遵守系统录屏权限；无 Python、OpenCV 或模型文件。
- 后台每轮间隔 33ms，实际帧率取决于截图与识别耗时。方向结果携带参数版本和采集时间，超过 300ms 的方向不显示。诊断图片只发给控制面板，最多 8 帧/秒、图片最长边 384px；同帧轮廓和端点沿原始截图坐标绘制，不写磁盘。
- YAML 配置位于系统应用配置目录的 `com.goldline.overlay/settings.yaml`：Mac 通常在 `~/Library/Application Support/`，Windows 通常在 `%APPDATA%`。
- 参数更新约 500 ms 后原子写入，退出前刷新。读取失败提示并使用默认值；写入失败提示并自动重试。
- 窗口位置使用物理桌面坐标，尺寸使用逻辑像素，轴心和识别框按窗口比例保存。旧版识别参数会迁移为夹子识别，过小的识别框会扩大；新设置保存后不会重复扩大。
- macOS 透明窗口使用 Tauri 的 `macOSPrivateApi`，此构建方式不面向 Mac App Store。

```sh
cargo run --manifest-path src-tauri/Cargo.toml --example detect_claw -- src-tauri/tests/fixtures/short-rope.png 40 95 80 80
```

四个数依次为截图中识别框的 X、Y、宽度、高度（像素）。最后可再传一个 PNG 输出路径，生成识别框、夹口两端连线（红色）和中垂线（黄色）叠加图。参考图只用于测试，不打包为应用资源。
